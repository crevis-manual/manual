1. 준비하기

1.1 PC 최소/권장사양

  • CPU : Intel Core i3 (최소), Intel Core i5 이상 (권장)
  • RAM : 2GB 이상 (최소), 8GB 이상 (권장)
  • O/S : Windows 7 (32bit / 64bit) 이상
  • LAN Card : Intel PRO/1000xT 이상
  • VGA : FHD 지원 (최소), UHD 지원 이상 (권장)

1.2 SDK

크래비스 GigE 카메라를 사용하려면 CREVIS에서 제공하는 SDK를 이용하여 영상을 받거나, GigE Vision을 지원하는 Image 라이브러리(Cognex, HALCON, Euresys, CVB 등)를 사용하여 영상을 취득할 수 있습니다.

  • 크래비스 SDK 다운로드 링크 : http://www.crevis.co.kr/upload/download/MCam40_SDK.zip

1.3 케이블

  • 데이터 통신을 위해 Category 5E 이상의 네트워크 케이블이 필요합니다.
  • 카메라에 DC 12V~24V 전원을 인가해야 합니다.
  • PoE+ (Power Over Ethernet+)를 사용할 경우, 12Pin 커넥터에는 외부 전원을 인가하지 마십시오.

1.4 방화벽 및 백신 프로그램

  • 안정적인 패킷 전송을 위해 방화벽 및 백신 프로그램을 끄거나 예외 처리해야 합니다.
  • Windows 7 : 시작 ▶ 제어판 ▶ Windows 방화벽 ▶ Windows 방화벽 설정 또는 해제
  • Windows 8 / 8.1 / 10 : 시작 ▶ 제어판 ▶ Windows Defender 방화벽 ▶ Windows Defender 방화벽 설정 또는 해제

1.5 주의사항

주의사항

  • 동작 온도(Performance guarantee temperature) : Case 온도 0℃ ~ +45℃, 센서 온도 +15℃
  • 주변 온도 변화에 따라 데이터 출력이 달라질 수 있으므로 일정하게 온도를 유지하십시오.
  • 주변 온도 변화에 따라 센서 쿨링으로 인한 소비전력이 증가할 수 있습니다.
  • 이더넷 허브를 통해 두 개 이상의 카메라를 연결하면 대역폭 문제가 발생할 수 있습니다.
  • UDP 통신은 데이터 전송을 보장하지 않습니다. 패킷 손실을 줄이기 위해 SDK 설치 시 제공되는 Installation Guide를 참고하여 카메라 및 네트워크 카드를 설정하십시오.
  • 필터 드라이버를 사용하기 위해서는 관리자 권한으로 실행하십시오. CamGuide는 자동으로 관리자 권한으로 실행됩니다.
  • 큰 패킷 사이즈는 패킷 손실을 최소화합니다. 단, 카메라의 패킷 사이즈는 네트워크 카드의 점보 프레임 또는 점보 패킷 사이즈보다 낮아야 합니다.

LED 상태창

  • - ‘Trigger Mode’가‘On’ 일경우에는트리거에의해노출이되고전송됩니다.
  • 3) Continuous

‘Acquisition Start’ 커맨드가입력된시점으로부터‘Acquisition Frame Rate’에정의된주기로 Image를 촬상하고전송합니다. Grab 중‘Acquisition Stop’ 커맨드가입력될경우, 현재노광중인 Image 까지는 Readout 하고전송한뒤 Acquisition 을멈추게됩니다. 노광이종료된시점에‘Acquisition Stop’ 커맨드가 입력되면진행중이던 Readout 까지마친뒤에 Acquisition 이종료됩니다.

  • - ‘Trigger Mode’가‘On’ 일경우에는트리거에의해노출이되고전송됩니다.

4.4.1 Exposure Mode

‘Timed’ 셔터방식은‘Exposure Time’에설정된시간만큼만노광이이루어지게됩니다. 트리거는단지 노광의시작시점을지정하는역할을합니다. 반면‘Trigger Width’ 셔터방식은트리거신호의 Pulse 폭이 유효한노광시간이됩니다.

4.4.2 Exposure Time

카메라의노광시간을설정합니다. 이시간은‘Exposure Mode 가‘Timed’로설정되어있는경우에만 적용됩니다. Freerun Mode 에서는‘Exposure Time’이 Frame 주기보다길어질경우, Frame Rate 이 감소하게됩니다.

카메라내부의실제노광신호는‘HD’ 타이머에의해발생하게됩니다. 이‘HD’ 타이머는수평방향의 Readout Size 와관련이있기때문에, 일반적으로 Image Width 가작을수록 HD 신호의주기도함께 단축됩니다. 또한영상전송 Bandwidth 와관련된파라미터(ex. Pixel Format, Device Throughput 등)를

변경할경우에도 HD 신호의주기가변경됩니다.

센서특성상 White Pixel 이발생할수있으므로 Long Exposure Time(수십 ms 이상)은권장하지

않습니다. 발생정도는주변환경(카메라/센서온도등)에따라다릅니다.

Chipset 이부착된 Multi-port 랜카드를사용하는것입니다. 그렇지못한경우에는각카메라의 Packet 전송을분산시켜 Host(수신부)의최대 Bandwidth 를초과하지않도록운용해야합니다. 예컨대‘Full Framed Mode’로각기다른‘Transfer Delay’를적용하면이미지전송시점을분산시킬수있습니다. 이경 우 Host 는순차별로이미지를수신하게됩니다.

또한‘Low Latency Mode’에서는‘Packet Delay’를사용하면이미지 Packet 간 Interval 이늘어나기때문 에사이시간을활용하여분산할수있습니다. 이경우 Host 는여러카메라의이미지를유사한시간대에 수신하게됩니다.

※ 유의사항

  • 1) ‘Low Latency Mode Enable’ 파라미터는카메라의시작시반영됩니다. 따라서모드변경시‘User

Set Save’ 커맨드이후재부팅이필요합니다.

  • 2) ‘Transfer Delay’ 기능은‘Low Latency Mode Enable’이‘False’ 일때에만설정가능합니다.

4.16.2 Gev Heartbeat Timeout

Heartbeat 는 PC 와카메라가연결되어있을때, 카메라는영상획득상태가아니더라도연결상태를 지속적으로체크하는기능입니다. 입력한‘Gev Heartbeat Timeout’ 시간을초과하도록 Heartbeat 패킷(또 는응답)이없을경우, 연결이끊어진것으로간주합니다. Host 및카메라모두연결이끊어졌다고판단하 면기존의연결을해제합니다.

4.16.3 Gev Heartbeat Disable

Heartbeat Timeout 기능의사용여부를결정할수있습니다. ‘False’로설정할경우 Heartbeat 타이머가 작동됩니다. 만일‘Gev Heartbeat Disable’을‘True’로설정할경우 Heartbeat 기능은비활성화됩니다. 이 때에는 Link 가끊긴경우카메라또는 Host 에서는 Link 끊김을감지할수없으므로사용에유의해야합 니다.

4.16.4 GevSCPSPacket Size

카메라가전송할 이미지패킷의전송단위입니다. 가장안정적인이미지패킷전송은이미지 Line Readout 과동일한주기로전송하는방법입니다. 이에따른설정은다음과같습니다. 자세한타이밍은 p.40 <Timing Diagram of Low Latency Mode> 그림을참고해주시기바랍니다.

(단, n 은패킷사이즈가점보프레임을초과하지않는범위의값)

4.16.5 GevSCPD

카메라의패킷사이의지연 시간을추가하는기능입니다. Packet Delay 를적용할경우패킷간의 Interval 이늘어나며전송대역폭이낮아지는효과가있습니다. 설정값은 Clock 단위로써시간으로의환 산식은다음과같습니다.

※ 유의사항 한 frame 내에서지연된총시간이프레임주기를넘어설경우다음프레임은누락됩니다. 따라서 Frame Rate 손실이발생합니다.
